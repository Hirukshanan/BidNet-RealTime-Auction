# TCP auction protocol

Transport is TCP on all local interfaces, with UTF-8 newline-delimited JSON.
Each frame has a case-sensitive `type` string and an object `payload`.
Jackson preserves quotes, backslashes and Unicode. Invalid frames return ERROR
without closing the connection.

## Connection and delivery contract

The server assigns a random bidder ID to each connection. JOIN_AUCTION returns
that ID; caller-supplied senderId/bidderId fields never control bid identity.
This is a connection identity, not an authenticated account. Reconnecting creates
a new identity. A connection may subscribe to multiple auctions by joining each.
Repeated joins are allowed and return current state with the same identity.

A client must join an auction before bidding on it. Joining subscribes it before
reading state, so an AUCTION_UPDATE can arrive before AUCTION_STATE. Accepted bids
produce a direct BID_RESULT and an AUCTION_UPDATE to every subscriber, including
the bidder. Rejected bids produce only BID_RESULT. There are no unsolicited
welcome frames, and ECHO does not subscribe a connection.

Each socket has one writer and a bounded 256-frame outbound queue. Failed or
slow clients whose queues fill are disconnected; they do not block other bidders.
Network operations happen after the engine has released its auction lock.
Concurrent operations may enqueue snapshot versions out of order: clients must
track the greatest version per auction and ignore older snapshots from any
message type. Equal versions represent the same state. A client must still show
the accepted/rejected outcome from a BID_RESULT even if its snapshot is older.
Do not assume that the next received frame is the reply to the latest command.
Use one independent socket reader and keep receiving while keyboard input is idle.

## Join an auction

The standard server entry point creates one in-memory auction, `demo`, starting
at `1000.00`. Restarting the server resets its state. Tests can inject an engine
with other auctions through `BidNetServer(int port, AuctionEngine engine)`.

```json
{"type":"JOIN_AUCTION","payload":{"auctionId":"demo"}}
```

Example response (the actual bidder ID is generated by the server):

```json
{"type":"AUCTION_STATE","payload":{"bidderId":"connection-1","snapshot":{"auctionId":"demo","status":"OPEN","startingPrice":"1000.00","currentPrice":"1000.00","minimumNextBid":"1000.00","highestBidderId":null,"version":0}}}
```

## Place a bid

Money is sent as a plain decimal string, not a JSON number. The wire parser
accepts an optional minus sign, digits and an optional fractional part, with a
maximum total length of 64 characters. Exponents, whitespace and plus signs are
rejected. The engine then checks positivity, two-decimal precision and the minimum.

```json
{"type":"PLACE_BID","payload":{"auctionId":"demo","amount":"1000.00"}}
```

```json
{"type":"BID_RESULT","payload":{"accepted":true,"reason":null,"snapshot":{"auctionId":"demo","status":"OPEN","startingPrice":"1000.00","currentPrice":"1000.00","minimumNextBid":"1050.00","highestBidderId":"connection-1","version":1}}}
```

Every subscriber receives the same immutable snapshot:

```json
{"type":"AUCTION_UPDATE","payload":{"snapshot":{"auctionId":"demo","status":"OPEN","startingPrice":"1000.00","currentPrice":"1000.00","minimumNextBid":"1050.00","highestBidderId":"connection-1","version":1}}}
```

A low bid returns `accepted:false`, `reason:"BID_TOO_LOW"`, and the unchanged
snapshot in BID_RESULT. Other engine reasons include NON_POSITIVE_AMOUNT and
TOO_MANY_DECIMAL_PLACES. All snapshot money fields are two-decimal strings;
version is a nonnegative integer. highestBidderId is null until a bid is accepted.
While status is OPEN, the highest bidder is the current leader, not a final winner.
Expiry, closure and final-winner events are separate work in issue #7.
See [the engine rules](auction-engine.md) for the five-percent calculation.

## ECHO diagnostic

```json
{"type":"ECHO","payload":{"message":"Hello BidNet"}}
```

```json
{"type":"ECHO_RESPONSE","payload":{"message":"Hello BidNet"}}
```

Any object payload is echoed unchanged. ECHO remains available before or after join.

## Errors

```json
{"type":"ERROR","payload":{"reason":"NOT_JOINED"}}
```

- INVALID_JSON: invalid JSON or trailing JSON values.
- INVALID_MESSAGE: invalid envelope, type or payload.
- UNSUPPORTED_TYPE: command is not ECHO, JOIN_AUCTION or PLACE_BID.
- INVALID_AUCTION_ID: auctionId is missing, blank or not a string.
- AUCTION_NOT_FOUND: the joined auction does not exist.
- NOT_JOINED: this connection has not joined the bid's auction.
- INVALID_AMOUNT: amount is missing, not a string or violates the wire format.

## Run on Windows or macOS

Install JDK 21 and Maven, then run from the repository root.

```text
mvn compile exec:java "-Dexec.mainClass=com.bidnet.server.BidNetServer" "-Dexec.args=5051"
```

In a separate terminal, start each console client:

```text
mvn exec:java "-Dexec.mainClass=com.bidnet.client.ConsoleClient" "-Dexec.args=127.0.0.1 5051"
```

| Command | Effect |
| --- | --- |
| `join <auctionId>` | Join an auction and show its current state |
| `bid <amount>` | Bid on the auction joined most recently |
| `echo <text>` | Test the connection |
| `help` | List the commands |
| `quit` | Disconnect and exit |

The client changes its current auction only when the server confirms a join with
AUCTION_STATE. A failed join leaves it unchanged, and a bid typed before the
confirmation arrives still targets the previous auction.

The client has one background socket reader and no read timeout, so updates appear
while it waits for keyboard input. It ignores snapshots older than the newest
version it has seen, and it exits if the connection ends. It has no heartbeat, so
it may not notice a silently lost network path until it next sends a command.

Choose a free port and use the same port on server and clients. On multiple
computers, use the server's reachable LAN address and allow the port through its
firewall. GitHub hosts source code; it does not run this TCP server.

## Verification

```text
mvn --batch-mode --no-transfer-progress verify
mvn "-Dtest=AuctionNetworkingTest" test
```

AuctionNetworkingTest uses real TCP sockets and OS-selected ports to verify join,
server-owned identities, accepted/rejected bids, subscriber isolation, concurrent
whole-frame delivery, consistent versions, validation and disconnect recovery.
TcpCommunicationTest preserves ECHO, Unicode, malformed-message recovery, shutdown
and the console entry-point checks. AuctionEngineTest checks the domain rules.
Windows/macOS CI must run on the integration branch after it is published.
