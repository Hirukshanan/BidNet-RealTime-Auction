# TCP auction protocol

Transport is TCP on all local interfaces, with UTF-8 newline-delimited JSON.
Each frame has a case-sensitive `type` string and an object `payload`.
Jackson preserves quotes, backslashes and Unicode. Invalid requests return
ERROR without closing the connection.

## Connection and delivery contract

The server assigns a random bidder ID to each connection. JOIN_AUCTION returns
that ID. Caller-supplied senderId or bidderId fields never control bid identity.
This is a connection identity, not an authenticated account. Reconnecting creates
a new identity.

A connection may subscribe to multiple auctions by joining each one. Repeated
joins return current state with the same bidder identity.

A client must join an auction before bidding on it. Joining subscribes the
connection before reading state, so AUCTION_UPDATE may arrive before AUCTION_STATE.

Accepted bids produce:

- A direct BID_RESULT to the bidder.
- An AUCTION_UPDATE to every subscriber, including the bidder.

Rejected bids produce only BID_RESULT.

There are no unsolicited welcome frames. ECHO does not subscribe a connection.

Each socket has one writer and a bounded 256-frame outbound queue. Failed clients
and slow clients whose queues fill are disconnected without blocking other bidders.
Network operations happen after the engine releases its auction lock.

Concurrent operations may enqueue snapshot versions out of order. Clients must
track the greatest version per auction and ignore older snapshots from any message
type. Equal versions represent the same state.

The accepted or rejected outcome from BID_RESULT must still be displayed even when
its snapshot is older than the latest known snapshot.

Clients must not assume that the next received frame replies to the latest command.
Use one independent socket reader and continue receiving while keyboard input is idle.

## Join an auction

The standard server entry point creates one in-memory auction named `demo`,
starting at `1000.00`. Restarting the server resets its state.

Tests can inject an engine containing other auctions through
`BidNetServer(int port, AuctionEngine engine)`.

Request:

```json
{"type":"JOIN_AUCTION","payload":{"auctionId":"demo"}}
```

Example response (the actual bidder ID and deadline are generated by the server):

```json
{"type":"AUCTION_STATE","payload":{"bidderId":"connection-1","snapshot":{"auctionId":"demo","status":"OPEN","startingPrice":"1000.00","currentPrice":"1000.00","minimumNextBid":"1000.00","highestBidderId":null,"deadline":"2026-11-10T10:00:00Z","version":0}}}
```

## Place a bid

Money is sent as a plain decimal string, not a JSON number.

The wire parser accepts an optional minus sign, digits and an optional fractional
part, with a maximum total length of 64 characters. Exponents, whitespace and plus
signs are rejected.

The engine checks positivity, two-decimal precision and the minimum allowed bid.

Request:

```json
{"type":"PLACE_BID","payload":{"auctionId":"demo","amount":"1000.00"}}
```

Accepted result:

```json
{"type":"BID_RESULT","payload":{"accepted":true,"reason":null,"snapshot":{"auctionId":"demo","status":"OPEN","startingPrice":"1000.00","currentPrice":"1000.00","minimumNextBid":"1050.00","highestBidderId":"connection-1","deadline":"2026-11-10T10:00:00Z","version":1}}}
```

Every subscriber receives the same immutable snapshot:

```json
{"type":"AUCTION_UPDATE","payload":{"snapshot":{"auctionId":"demo","status":"OPEN","startingPrice":"1000.00","currentPrice":"1000.00","minimumNextBid":"1050.00","highestBidderId":"connection-1","deadline":"2026-11-10T10:00:00Z","version":1}}}
```

A low bid returns `accepted:false`, `reason:"BID_TOO_LOW"` and the unchanged
snapshot:

```json
{"type":"BID_RESULT","payload":{"accepted":false,"reason":"BID_TOO_LOW","snapshot":{"auctionId":"demo","status":"OPEN","startingPrice":"1000.00","currentPrice":"1000.00","minimumNextBid":"1050.00","highestBidderId":"connection-1","version":1}}}
```

Other engine rejection reasons include NON_POSITIVE_AMOUNT and
TOO_MANY_DECIMAL_PLACES.

All snapshot money fields are two-decimal strings. The version is a nonnegative
integer. highestBidderId is null until a bid is accepted.

While status is OPEN, the highest bidder is the current leader, not a final winner.
See [the engine rules](auction-engine.md) for the five-percent calculation.

## Auction expiry

The UTC `deadline` in every snapshot is authoritative and exclusive: a bid is
eligible only while the server clock is before it. At or after the deadline, the
engine rejects the bid and freezes the final winner and price. Closure increments
the snapshot version exactly once.

Every subscriber receives one final event, whether the scheduler or a late bid
observes expiry first:

```json
{"type":"AUCTION_ENDED","payload":{"snapshot":{"auctionId":"demo","status":"CLOSED","startingPrice":"1000.00","currentPrice":"1000.00","minimumNextBid":"1050.00","highestBidderId":"connection-1","deadline":"2026-11-10T10:00:00Z","version":2}}}
```

If no bid was accepted, `highestBidderId` is `null`, `currentPrice` remains the
starting price, and the close transition moves the version from `0` to `1`.
A late bid receives `BID_RESULT` with `accepted:false`, reason
`DEADLINE_REACHED`, and the same final snapshot. Later bids receive
`AUCTION_CLOSED`. See [the expiry contract](auction-expiry.md).

## ECHO diagnostic

Request:

```json
{"type":"ECHO","payload":{"message":"Hello BidNet"}}
```

Response:

```json
{"type":"ECHO_RESPONSE","payload":{"message":"Hello BidNet"}}
```

Any object payload is echoed unchanged. ECHO remains available before or after join.

## Errors

Example:

```json
{"type":"ERROR","payload":{"reason":"NOT_JOINED"}}
```

Reasons:

- INVALID_JSON: invalid JSON or trailing JSON values.
- INVALID_MESSAGE: invalid envelope, type or payload.
- UNSUPPORTED_TYPE: command is not ECHO, JOIN_AUCTION or PLACE_BID.
- INVALID_AUCTION_ID: auctionId is missing, blank or not a string.
- AUCTION_NOT_FOUND: the requested auction does not exist.
- NOT_JOINED: this connection has not joined the bid's auction.
- INVALID_AMOUNT: amount is missing, not a string or violates the wire format.

## Run on Windows or macOS

Install JDK 21 and Maven, then run from the repository root.

Start the server:

```text
mvn compile exec:java "-Dexec.mainClass=com.bidnet.server.BidNetServer" "-Dexec.args=5051"
```

In a separate terminal, start each console client:

```text
mvn exec:java "-Dexec.mainClass=com.bidnet.client.ConsoleClient" "-Dexec.args=127.0.0.1 5051"
```

Commands:

| Command | Effect |
| --- | --- |
| `join <auctionId>` | Join an auction and show its current state |
| `bid <amount>` | Bid on the most recently confirmed auction |
| `echo <text>` | Test the connection |
| `help` | List available commands |
| `quit` | Disconnect and exit |

Example session:

```text
join demo
bid 1000.00
```

Wait for the join confirmation before entering the bid.

The client changes its current auction only when the server confirms a join with
AUCTION_STATE. A failed join leaves it unchanged. A bid typed while a new join is
pending still targets the previous confirmed auction.

The client has one background socket reader and no read timeout, so updates appear
while keyboard input is idle. It ignores snapshots older than the newest version
already received and exits if the connection ends.

It has no application heartbeat, so detecting a silently lost network path depends
on operating-system networking behavior and subsequent socket activity.

Choose a free port and use the same port on the server and clients.

For multiple computers, replace `127.0.0.1` with the server computer's reachable LAN
address and allow the server port through its firewall.

GitHub hosts source code; it does not run the TCP server.

## Verification

Run the complete automated checks:

```text
mvn --batch-mode --no-transfer-progress verify
```

Run the server networking tests:

```text
mvn "-Dtest=AuctionNetworkingTest" test
```

Run the console client tests:

```text
mvn "-Dtest=ConsoleClientTest" test
```

AuctionNetworkingTest uses real TCP sockets and OS-selected ports to verify join,
server-owned identities, accepted and rejected bids, subscriber isolation,
concurrent whole-frame delivery, consistent versions, validation and disconnect
recovery.

TcpCommunicationTest verifies ECHO, Unicode, malformed-message recovery, shutdown
and the console entry point.

AuctionEngineTest checks the domain rules.

ConsoleClientTest checks commands, live receiving, failed-join recovery,
snapshot-version handling and connection termination. Final-event handling is
also tested using AUCTION_ENDED frames.

Windows and macOS CI results must be checked on the latest PR revision.
